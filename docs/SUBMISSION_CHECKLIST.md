# Hackaform Phase 2 Submission Checklist

Use this list to keep the four Phase 2 submissions separate.

## Part 1 — Project pitch

- [ ] Upload `Hackaform_Phase_2_Project_Pitch.pdf` or the editable DOCX from the Desktop.
- [ ] Include the 6-slide pitch deck if the submission allows supporting material.
- [ ] Confirm the pitch is 1–2 pages and covers the business problem, process, timeline, scope, risks, and ERD.

## Part 2 — MVP discussion

- [ ] Start Flask and React using the README instructions.
- [ ] Demonstrate `GET /api/health` and the React catalogue loading data from `/api/events`.
- [ ] Share the requested screenshot, recording, or discussion response in Canvas.

## Part 3 — Final full-stack assignment

- [ ] Push the tested code to the public `Svnd3/hackaform` GitHub repository.
- [ ] Open the repository in a private/incognito window to confirm it is public.
- [ ] Submit the GitHub repository URL in Canvas.
- [ ] If deployed later, add the live URL to the README and Canvas submission.

## Part 4 — Showcase discussion

- [ ] Record a walkthrough of no more than 10 minutes using `docs/PHASE2_DEMO.md`.
- [ ] Upload the video and verify that classmates/instructors can open it.
- [ ] Attach the final showcase slide deck from the Desktop.
- [ ] Attach or paste the written reflection.
- [ ] Watch one peer presentation and customize `docs/PEER_REVIEW_TEMPLATE.md` with real evidence before posting it.

## Final pre-submission check

- [ ] Run `npm run check`.
- [ ] Run `ruff check .` and `pytest --cov=app` inside `server/`.
- [ ] Confirm no passwords, database credentials, or `.env` files are committed.
- [ ] Rehearse the organizer and attendee demo accounts from the README.
- [ ] Check spelling, links, audio clarity, and sharing permissions.
